Project Description

A full AJAJ (Asynchronous JavaScript and JSON) RESTful web service built on top of a MySQL student records database. Converted from a Unit 2 Ex2 web app into a proper service/client architecture with separate ServiceProvider and ServiceClient folders, modeled after the MurachDB_Sample3 pattern.

The project includes an index page with navigation links, two AJAJ web service clients (single record and all records via innerHTML), and two additional raw JSON API testers for direct service verification.

Architecture & Components

Folder Structure
  • schb_unit2_ex3/ — Root with index.html home page
  • ServiceProvider/class_lib/ — PHP classes: schb_Students_API.php, schb_SelectOne_API.php, DB connection
  • ServiceProvider/ — RESTful provider endpoints returning raw JSON
  • ServiceClient/ — HTML/JS AJAJ clients consuming the service via innerHTML

Index Page Links (schb_unit2_ex3 HOME Page)
  • 1. Run all Web Service Testers
  • 2. Display a Single Student Record using AJAJ Web Service (innerHTML)
  • 3. Display All Student Records using AJAJ Web Service (innerHTML)
  • 4. Test schb_Students_API (view raw JSON for all records)
  • 5. Test schb_SelectOne_API (view raw JSON for a single record)

Key Features

  • Procedural tester confirms DB connection, runs SHOW DATABASES, SHOW TABLES, and SELECT * FROM schb_students
  • OOP tester includes selectOne() — returns a single student record by ID
  • All-records client: "Please click to view all student records" button returns 5 students via JSON, displayed via innerHTML
  • Single-record client: Student ID input field; submitting ID 2 returns "Record found: 2 Bob Martinez Information Technology 3.42"
  • schb_Students_API raw JSON tester returns full array of all 5 student records
  • schb_SelectOne_API raw JSON tester accepts ?student_id=3 and returns {"record":"3 Carol Williams Cybersecurity 3.91","status":"found"}

Sample Code — schb_SelectOne_API.php (Single Record Endpoint)

<?php
// ServiceProvider/schb_SelectOne_API.php
header('Content-Type: application/json');
header('Access-Control-Allow-Origin: *');

require_once 'class_lib/DB.php';
require_once 'class_lib/StudentsDB.php';

$id = isset($_GET['student_id']) ? intval($_GET['student_id']) : 0;

$db  = new DB();
$conn = $db->getConnection();
$studentsDB = new StudentsDB($conn);

$result = $studentsDB->selectOne($id);

if ($result) {
    echo json_encode(['record' => $result, 'status' => 'found']);
} else {
    http_response_code(404);
    echo json_encode(['record' => '', 'status' => 'not found']);
}
?>

Sample Code — AJAJ Client (innerHTML, Single Record)

// ServiceClient/schb_SelectOne_Client.html — JavaScript
function submitForm() {
    const studentId = document.getElementById('studentId').value;
    const xhr = new XMLHttpRequest();

    xhr.onreadystatechange = function () {
        if (this.readyState === 4 && this.status === 200) {
            const data = JSON.parse(this.responseText);
            const msg  = data.status === 'found'
                ? 'Record found:<br>' + data.record
                : 'No record found for that ID.';
            document.getElementById('messageContents').innerHTML = msg;
        }
    };

    xhr.open('GET',
        '../ServiceProvider/schb_SelectOne_API.php?student_id=' + studentId,
        true);
    xhr.send();
}

Dynamic — Unit 1 Ex4: Sailboat RESTful AJAX-JSON-PHP Web Service

Project Description

A PHP RESTful web service built around a Sailboat OOP class, a SailboatDB database emulator, and a SailboatAPI application interface layer — modeled after the Unit 1 Ex3 Product/ProductDB/API pattern. The service is consumed by two clients: a SailboatAPI_Tester.php page for direct class testing, and a full Sailboat RESTful Client HTML page that queries the service via AJAX and displays results in a formatted table.

Architecture & Components

  • Sailboat.php — OOP class with private properties ($boatName, $ownerName, $numberOfSails, $price), default constructor, getters/setters, and a getFormattedPrice() method returning a formatted currency string
  • SailboatDB.php — Database emulator with getSailboat($name) method; includes 5+ boats (Windchaser, Sunset, Horizon, Ocean's Dream, SeaBreeze); returns "Unknown Sailboat" for unrecognized names
  • SailboatAPI.php — RESTful API interface exposing a default constructor and a method that accepts a sailboat name string, calls SailboatDB::getSailboat(), and returns the JSON-encoded result
  • SailboatAPI_Tester.php — Simple PHP tester page with a form input and "Test SailboatDB API" button; displays raw result fields (Boat Name, Owner Name, Number of Sails, Price, Formatted Price)
  • Sailboat_Client.html — Full RESTful client with styled table output; accepts a sailboat name, calls the PHP provider via AJAX, and renders a Sailboat Information table with Property/Value columns

Key Features

  • OOP PHP class with private fields, default constructor, and full getter/setter methods
  • DB emulator returns a populated Sailboat object for valid names, or an "Unknown Sailboat" default object for invalid input
  • RESTful provider returns JSON; client consumes it via AJAX without page reload
  • Tested with valid boats: Windchaser (John Smith, 3 sails, $45,000), Sunset (Michael Brown, 2 sails, $28,000), Horizon (Robert Davis, 4 sails, $62,500)
  • Invalid name handling: "Sea Breeze" returns Unknown Sailboat / Unknown Owner / 0 sails / $0.00

Sample Code — Sailboat.php (OOP Class)

<?php
class Sailboat {
    private $boatName;
    private $ownerName;
    private $numberOfSails;
    private $price;

    // Default constructor
    public function __construct() {
        $this->boatName      = '';
        $this->ownerName     = '';
        $this->numberOfSails = 0;
        $this->price         = 0;
    }

    // Getters
    public function getBoatName()      { return $this->boatName; }
    public function getOwnerName()     { return $this->ownerName; }
    public function getNumberOfSails() { return $this->numberOfSails; }
    public function getPrice()         { return $this->price; }

    // Setters
    public function setBoatName($n)      { $this->boatName = $n; }
    public function setOwnerName($n)     { $this->ownerName = $n; }
    public function setNumberOfSails($n) { $this->numberOfSails = $n; }
    public function setPrice($p)         { $this->price = $p; }

    // Returns formatted currency string
    public function getFormattedPrice(): string {
        return '$' . number_format($this->price, 2);
    }
}
?>

Sample Code — SailboatDB.php (DB Emulator)

<?php
require_once 'Sailboat.php';

class SailboatDB {
    public function getSailboat($name): Sailboat {
        $boat = new Sailboat();

        switch (strtolower(trim($name))) {
            case 'windchaser':
                $boat->setBoatName('Windchaser');
                $boat->setOwnerName('John Smith');
                $boat->setNumberOfSails(3);
                $boat->setPrice(45000);
                break;
            case 'sunset':
                $boat->setBoatName('Sunset');
                $boat->setOwnerName('Michael Brown');
                $boat->setNumberOfSails(2);
                $boat->setPrice(28000);
                break;
            case 'horizon':
                $boat->setBoatName('Horizon');
                $boat->setOwnerName('Robert Davis');
                $boat->setNumberOfSails(4);
                $boat->setPrice(62500);
                break;
            // ... additional boats
            default:
                $boat->setBoatName('Unknown Sailboat');
                $boat->setOwnerName('Unknown Owner');
                $boat->setNumberOfSails(0);
                $boat->setPrice(0);
        }
        return $boat;
    }
}
?>

Project Description

A Windows Communication Foundation (WCF) web service implementing a calculator with four arithmetic operations: Addition, Subtraction, Multiplication, and Division. The service is hosted via BasicHttpBinding at localhost:55307/Service1.svc and exposes both synchronous and asynchronous operation contracts (Add(), AddAsync(), etc.) for each operation.

The project includes two clients: the built-in WCF Test Client for testing the SOAP service directly, and a C# Console App that consumes the service and prompts the user to choose an operation and enter two numbers. All four operations were tested and verified.

Key Features

  • WCF service with IService1 contract exposing Add, Subtract, Multiply, Divide operations
  • Both synchronous and async operation contracts generated automatically
  • Tested via WCF Test Client — inputs two System.Double values, returns System.Double result
  • Service description accessible in browser at localhost:55307/Service1.svc
  • Console App client prompts user to choose operation (1–4) and enter two numbers
  • All four arithmetic functions tested and confirmed working

Sample Code — WCF Service Contract

// IService1.cs — Service Contract
[ServiceContract]
public interface IService1
{
    [OperationContract]
    double Add(double a, double b);

    [OperationContract]
    double Subtract(double a, double b);

    [OperationContract]
    double Multiply(double a, double b);

    [OperationContract]
    double Divide(double a, double b);
}

// Service1.svc.cs — Implementation
public class Service1 : IService1
{
    public double Add(double a, double b)      => a + b;
    public double Subtract(double a, double b) => a - b;
    public double Multiply(double a, double b) => a * b;
    public double Divide(double a, double b)   => a / b;
}

Sample Code — Console App Client

// Program.cs — Console App consuming the WCF service
static void Main(string[] args)
{
    ServiceReference1.Service1Client client = new ServiceReference1.Service1Client();

    Console.WriteLine("Choose equation type:");
    Console.WriteLine("1. Addition\n2. Subtraction\n3. Multiplication\n4. Division");
    Console.Write("Enter choice (1-4): ");
    int choice = int.Parse(Console.ReadLine());

    Console.Write("Enter first number: ");
    double a = double.Parse(Console.ReadLine());
    Console.Write("Enter second number: ");
    double b = double.Parse(Console.ReadLine());

    double result = choice switch
    {
        1 => client.Add(a, b),
        2 => client.Subtract(a, b),
        3 => client.Multiply(a, b),
        4 => client.Divide(a, b),
        _ => throw new ArgumentException("Invalid choice")
    };

    Console.WriteLine($"Result: {result}");
    client.Close();
    Console.WriteLine("Press any key to exit...");
    Console.ReadKey();
}

Project Description

A real-time voting web application built with Node.js and Socket.IO. Multiple users can simultaneously vote on a preferred free-time activity, with live vote results pushed to all connected clients instantly via WebSockets — no page refresh required.

Key Features

  • Real-time vote updates via Socket.IO broadcast to all connected clients
  • Multi-tab simultaneous voting — all tabs update live
  • Duplicate-vote prevention — submit button disabled after voting
  • Admin reset functionality — clears all vote counters across all clients instantly
  • Event-driven architecture: vote → server increments → io.emit('update') → DOM re-renders
  • Voting activities: Video Games, Reading, Crafty Hobbies, Physical Activity, Board Games

Architecture

3-Tier Real-Time Event-Driven Flow
  • Client (app.js / index.html) ↔ Socket.IO ws:// layer ↔ Server (server/index.js)
  • On connect: Server emits current vote totals to the new socket
  • On vote event: Server increments the correct counter; io.emit broadcasts to all clients
  • On reset event: Server zeroes all counters; io.emit clears all clients
  • Client update handler: Re-renders emoji counters live — no page reload
